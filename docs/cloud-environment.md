# 클라우드 환경 설정

현재 인스턴스에서는 frozen 의존성 설치, 실제 CPU Player, 로컬 HTTP 작업, 서비스 재시작을
검증했습니다. 설치 스크립트를 연속 두 번 실행했고 서비스 시작도 반복 실행했습니다.

환경 설정 초안에 저장한 필드:

- `install_script`: 기존 체크아웃에서 설치된 Python 3.11/3.12를 골라 uv frozen 설치와 doctor 실행.
- `start_skill`: 기존 격리 체크아웃 사용, 서비스 시작/재사용, 실제 HTTP Player readiness 검사,
  안전한 중지·재시작, 상태/로그 위치, 외부 도구 승인·미검증 범위.
- `network.allowed_domains`: 기존 패키지 관리자 preset을 보존하고 custom 도메인에
  `huggingface.co` 추가. 모델 카드 확인이 차단된 실제 요청을 근거로 저장했습니다.

저장 결과는 `status: saved`, `requires_publish: true`입니다. 저장만으로 스크립트 실행,
현재 네트워크 적용, 환경 게시 또는 새 머신 복원이 이루어진 것은 아닙니다. 환경 설정에서
변경을 검토·저장하고 게시해야 합니다. 추가 모델 파일 다운로드가 다른 목적지로 이동하면
해당 오류와 목적지를 확인한 뒤 필요한 도메인만 추가해야 합니다.

기본 CPU 흐름에는 외부 API key가 필요하지 않습니다. 로컬 API token은 각 서버 시작 시
생성하며 Git에서 제외합니다. 체크아웃은 `/workspace/Universal-Game-Agent`를 사용합니다.
클라우드 작업은 이미 격리되어 있으므로 별도 worktree를 만들지 않습니다.

소스는 현재 로컬 커밋에 있습니다. 원격 main과 새 작업 복원은 검증하지 않았습니다.
스냅샷 파일 상태, 저장된 설정, 원격 Git 반영, 실제 서비스 프로세스는 별개의 상태입니다.
